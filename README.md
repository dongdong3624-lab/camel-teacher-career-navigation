# 駱駝教師生涯導航｜網站起始套件

本 ZIP 內含四個檔案：

1. `schema.sql` — PostgreSQL 初始資料庫結構。
2. `index.html` — 教師生涯導航互動式前端原型。
3. `competency_models.json` — 三種職位能力模型的種子資料。
4. `README.md` — 安裝、資料規則、限制與後續建置說明。

## 一、目前版本定位

這是可供檢視與開發接續的起始套件，不是已部署的正式網站。`index.html` 可直接用瀏覽器開啟，能展示頁面流程與原型互動；但尚未連接 SQL 資料庫、正式登入、Google OAuth、伺服器端權限或雲端備份。前端原型的資料不保證在重新整理後保留。

## 二、已納入的功能方向

- 教師工作區：首頁總覽、能力自我盤點、職涯發展計畫、每週任務追蹤。
- 管理工作區：能力模型草案編輯與發布流程示意。
- 職位固定為：行政、導師、科任教師。
- 計畫模式：現職能力盤點、目標職位發展、現職盤點＋目標職位發展。
- 追蹤頻率以每週任務與每週回顧為主，不建立每日任務。
- 薪資資料僅預留 `salary_grade` 薪級欄位，不記錄實際薪資金額。
- 初期評分採固定規則；AI 不決定評分，僅為未來整合保留空間。
- 教師個人結果應只有本人可讀；管理員預設僅查看去識別化彙整統計。
- 能力內容採版本化：已發布版本不可原地修改，修改應建立新版本；歷史評估保留原模型、量尺與規則快照。

## 三、快速檢視

1. 解壓縮 ZIP。
2. 直接用 Safari、Chrome 或 Edge 開啟 `index.html`。
3. 在「能力自我盤點」選擇職位，填完 1–5 分並查看示意摘要。
4. 在「職涯發展計畫」設定目前職位、目標職位及計畫模式。
5. 在「每週任務追蹤」操作每週任務。
6. 在「能力模型管理」檢視討論中的草案能力項目。

## 四、資料庫初始化

本套件的 SQL 以 PostgreSQL 15+ 為目標。請先建立測試資料庫，再使用 `psql` 執行，例如：

```bash
psql "postgresql://USER:PASSWORD@HOST:5432/DATABASE" -f schema.sql
```

請勿把正式資料庫帳密放入 HTML 或任何前端檔案。此 SQL 建立資料表、外鍵、檢查條件與索引，並初始化三個職位；它不會建立登入帳號、密碼、完整的 RLS 政策或正式的模型發布觸發器。

## 五、建議的正式系統架構

- 前端：保留或重製 `index.html` 介面，改為呼叫後端 API。
- 後端：提供登入、角色授權、模型管理、評估提交、分數計算、每週任務與統計 API。
- 身分驗證：採用成熟身分服務處理電子郵件／密碼與 Google 登入；不要自行保存明文密碼。
- 資料庫：PostgreSQL；正式版啟用最小權限、備份、稽核與資料保留政策。
- 部署：使用 HTTPS，並分開管理開發、測試與正式環境的密鑰。

## 六、評分規則草案

- 每題 1–5 分；必填題目需完成後才提交。
- 能力分數建議以題目加權平均計算。
- 能力差距建議值：`max(0, 目標等級 - 能力分數)`；可同時保存帶正負號的差距值。
- 優先排序建議：差距由大到小，再依職位能力權重由大到小，最後以固定排序維持一致性。
- 不預先定義跨能力的總分；避免在尚未確認方法前產生誤導性總評。
- 目前 JSON 內的能力名稱、說明、目標等級和權重皆為討論草案，不是官方標準，正式使用前應由教師代表與專業人員審查。

## 七、正式上線前必要工作

- 確認每項能力的正式定義、可觀察行為指標、題目與量尺描述。
- 完成模型草稿、檢核、發布、封存與版本不可變更機制。
- 實作登入、Google OAuth、帳號連結與角色管理。
- 實作教師只能存取自己的評估、計畫、任務及反思資料。
- 實作管理員彙整報表、去識別化與小樣本抑制。
- 加上稽核紀錄、資料匯出／刪除流程、備份與還原演練。
- 進行無障礙、跨瀏覽器、資安與個資法遵循檢查。
- 完成測試資料、API 規格、部署設定及正式環境驗收。

## 八、隱私與安全注意事項

能力自評、職涯規劃及每週反思可能包含個人或工作敏感資訊。正式版應明確告知用途、保存期間、存取對象與刪除方式，限制非必要蒐集，並避免將可識別個人的明細提供給管理員。資料庫結構只是基礎，不能取代後端授權、資料庫列級安全（RLS）、加密、稽核及組織治理。
